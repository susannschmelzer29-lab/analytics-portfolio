# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository purpose

This is a **data analytics portfolio**, not a single application. It's a collection of independent,
numbered projects (`01_...` through `08_...`) documenting a career-changer's progression from
statistics/SQL fundamentals to full end-to-end analytics pipelines. Each project is self-contained
with its own README, data, and (where applicable) code — there is no shared build system, package
manifest, or test suite across the repo. Treat each numbered folder as its own working directory
when developing.

## Project index

| # | Folder | Stack | Nature |
|---|--------|-------|--------|
| 01 | `01_statistics_foundations` | Jupyter/pandas | Descriptive stats exploration |
| 02 | `02_ab_testing_statistics` | Python | Hypothesis testing exploration |

| 05 | `05_python_analytics_workflow` | Jupyter/pandas | Data cleaning pipeline (messy → clean CSV) |
| 06 | `06_automation_reporting` | Python script | Automated report generator, **consumes 05's output** |

Projects 01–06 are learning exercises (small simulated datasets); 07 and 08 are the mature,
end-to-end portfolio pieces meant to be presented to stakeholders.

## Commands by project type

**SQL projects (03, 04)** — database is built from `.sql` files, never committed (`*.db` is gitignored):

```powershell
Get-Content schema.sql, seed_data.sql | sqlite3 foundations.db   # (or advanced.db for 04)
Get-Content queries\<name>.sql | sqlite3 foundations.db
```

On non-PowerShell shells, concatenate instead: `cat schema.sql seed_data.sql | sqlite3 <db>`.

**Notebook projects (01, 05, 08)** — open and run the `.ipynb` directly, or execute headlessly:

```powershell
jupyter nbconvert --to notebook --execute --output executed.ipynb <notebook>.ipynb
```

**06 (depends on 05's output)** — expects `data/sales_clean.csv` (05's cleaned output) to exist,
then run `python generate_report.py` to regenerate charts + `report.md` into `./output/`.

**07** — `media_consumption_analysis.py` reads only the small pre-aggregated CSVs in `data/`
(not the 1.45M-row raw JSON, which is gitignored); run it directly with `python media_consumption_analysis.py`.
It resolves paths relative to its own file location, so it works from any invocation directory.

**08 (Rossmann)** — has its own project-scoped `CLAUDE.md` at
[08_rossmann_sales_analysis/CLAUDE.md](08_rossmann_sales_analysis/CLAUDE.md) with binding rules for
that folder specifically (PowerShell commands one at a time, no here-strings, Docker-headless-by-default).
Read it before working there. Quick reference:

```powershell
pip install -r requirements.txt
jupyter nbconvert --to notebook --execute --output executed.ipynb rossmann_sales_analysis.ipynb
python check_results.py
# or via Docker:
docker build -t rossmann-sales-analysis .
docker run --rm -v ${PWD}/data:/app/data -v ${PWD}/output:/app/output rossmann-sales-analysis
```

## Architecture notes

- **No shared code or dependencies.** Each project's Python code is self-contained (only 08 has a
  `requirements.txt`); there is no shared library, `src/`, or top-level package.
- **Raw/large data is never committed.** Large source files (Kaggle `train.csv`, HuffPost/ABC News
  raw JSON, generated `*.db` files, generated master CSVs like `rossmann_master_tableau.csv`) are
  excluded via `.gitignore`. Only small samples or pre-aggregated CSVs live in the repo — full data
  is fetched/mounted locally or generated by re-running the pipeline.
- **Pipelines end in Tableau, not in the repo.** Both flagship projects (07, 08) follow the same
  shape: raw data → Python/pandas aggregation → small CSVs checked into `data/`/`output/` →
  visualized in an external Tableau dashboard (linked from the project's README, not stored here).
- **Cross-project dependency:** 06 is not standalone — it reads the cleaned output that 05
  produces. If working on 06, check that 05's `data/clean/sales_clean.csv` output is available.
