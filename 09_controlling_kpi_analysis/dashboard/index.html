Reading the variance controlling note

Large single-month swings are often calendar effects, not performance: e.g. Easter fell in March 2013 but April 2014, so March 2014 shows a negative variance and April 2014 a positive one against a prior-year-month plan. A controller separates such timing shifts from genuine trend before acting.

Assumptions & Method

🔍 Full transparency by design: every euro cost/profit figure in this cockpit comes from the parameters below. Change one, re-run the notebook, and the whole dashboard updates — the honest way to present modelled numbers.

Model assumptions not real Rossmann figures

Planning method

PlanDaily(store, year, month)
  = mean(prior-year same-month daily sales) × (1 + 3%)
  • Baseline: 2013 → plans 2014, 2014 → plans 2015.
  • Seasonal: uses the same month a year earlier, so variance is not distorted by seasonality.
  • Variance = Actual − Plan, in € and as % of plan, at day / month / store / store-type level.

Cost & profit model contribution-margin accounting

  • Variable cost = Sales × ratio[StoreType] (COGS + variable opex).
  • Contribution margin (DB I) = Sales − variable cost.
  • Fixed cost = €900 × open trading days (rent, base staffing, utilities).
  • Operating profit = contribution margin − fixed cost.
  • Flat fixed cost means low-revenue stores can fall below break-even — surfaced as loss-making stores.

Limitations

  • No real financials — the dataset has only sales/customers/promo; plan and all costs are modelled.
  • Plan design is one valid choice among several (moving average, top-down, bottom-up); results depend on it.
  • Flat growth target ignores store-specific potential, cannibalisation and competition dynamics.
  • Simplified cost model — one variable ratio per store type + one flat daily fixed cost.
  • 2015 is year-to-date (Jan–Jul); closed and zero-sales days are excluded, consistent with project 08.
